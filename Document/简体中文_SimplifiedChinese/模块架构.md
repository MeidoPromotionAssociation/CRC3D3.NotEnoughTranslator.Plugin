# NotEnoughTranslator 模块架构

[English](../English/ModuleArchitecture.md) | [返回首页](../../README.md) | [翻译与资源指南](翻译指南.md)

本文面向插件开发与接入工作，说明当前骨架的职责边界。资源格式与翻译包制作方法见[翻译指南](翻译指南.md)。

## 1. 当前实现范围

| 模块 | 已实现 | 尚未接入或验证 |
| --- | --- | --- |
| UI / I2 | CSV 加载、中央查询 Hook、参数与 AdvancedFormat 处理、强制刷新 | 实机 UI 覆盖率与字体适配 |
| 通用文本 | JSONL 加载、精确匹配、正则替换、捕获组二次翻译、查询接口 | TMP / uGUI / 剧本等具体显示入口 |
| 纹理替换 | PNG / JPG / JPEG 资源索引、按纹理名读取数据、重载与卸载 | 游戏资源加载和 UI 图片替换入口 |

这是基础骨架，不代表已经覆盖游戏全部文本或图片。三个模块可以独立启用或关闭。

XUAT 互操作是共享设施，不是第四个翻译模块；它保护已登记的 NET 译文，但不会自动补齐通用文本显示 Hook。

## 2. 架构约束

- 不注册新语言，不新增 `LanguageSource`，不修改游戏语言或 `Product.supportMultiLanguage`。
- 不提供 JAT 的译文语言选择或多语言字符串切分；翻译包直接提供要显示的译文。
- 不做 LRU 或文本命中/未命中缓存。正则在加载时编译，查询时直接匹配。
- XUAT 防重译只登记已返回的译文，不保存原文到译文的查询缓存，也不添加、检测或剥离特殊标记。
- 正则使用 .NET 语法，保留捕获内容的二次精确翻译，不做自定义 `Unescape`。
- 通用文本模块只读取 JSONL，不引入 TXT 兼容层。
- 不移植旧 NGUI、COM3D2 文件系统或未经验证的全局 TMP setter 补丁。
- 翻译发生在显示或查询边界，不就地改写游戏业务数据。

## 3. 数据流

以下路径相对于 `BepInEx/NotEnoughTranslator`，沿用 JAT 的模块边界，但没有语言目录：

| 模块 | 资源加载 | 导出输出 |
| --- | --- | --- |
| UI / I2 | `UI/Text` | `Dump/UI/Text` |
| 通用文本 | `Text` | `Dump/Text` |
| 纹理替换 | `Texture` | `Dump/Texture` |

各加载器只扫描自己的资源子树，不扫描公共根目录或导出目录。ZIP 翻译包也必须放入对应文本模块的子树。

```text
UI/Text 下的 CSV / ZIP
  -> AsyncTranslationLoader
  -> TranslationLoadResult.I2Terms
  -> UITranslateManager
  -> UITextTranslatePatch
  -> I2 显示流程

Text 下的 JSONL / ZIP
  -> AsyncTranslationLoader
  -> TextTranslations / TextRegexTranslations
  -> TextTranslateManager
  -> 待接入的文本显示 Hook

Texture 下的图片
  -> TextureReplacementCatalog 路径索引
  -> TextureReplaceManager
  -> 待接入的资源或图片显示 Hook
```

两个文本模块共享加载基础设施，但资源通道和消费端彼此分开。`TranslationCatalog` 承担精确与正则查询，`ResourceModule<T>` 负责加载任务和主线程结果发布。

## 4. UI / I2 查询覆盖

目标是 CRC 版本的 `LocalizationManager.TryGetTranslation`，包含新增的 `Localize.AdvancedFormat` 参数。找不到预期签名时，记录错误并停用 UI 模块，而不是强行切换语言。

查询行为：

1. 指定了 `overrideLanguage` 时，不覆盖原结果；该调用中的嵌套 term 查询也不覆盖。
2. 自定义字典未命中时，保留原译文与成功标志。
3. 原 term 元数据为非文本类型时，不将资源标识当作文字替换。
4. 命中后，对新译文按原条件执行参数替换、RTL 处理和 `AdvancedFormat.Format`。
5. 全部处理成功且结果不是空白时，才替换译文并设置成功标志。
6. 处理异常时保留原结果，同一 term 每轮资源加载只警告一次。

不需要修改游戏语言列表、语言索引或 Source 优先级。UI 译文格式要求见[翻译指南](翻译指南.md)。

## 5. 生命周期与线程

三个管理器均提供 `Init` / `Reload` / `Unload`，在 Unity 主线程调用。资源加载由完成回调驱动，不再逐帧调用 `Tick`。

- 翻译文件读取、JSON / CSV 解析、正则编译与纹理路径扫描在后台执行，不调用 Unity API。
- 等待加载任务时捕获 Unity 同步上下文，完成后回到主线程发布结果，不轮询任务状态。
- 重载期间保留上次快照；被取消或过期的任务不会回写。
- 文件读取失败保留旧快照；成功加载空目录会清空该模块旧资源。
- 纹理字节在查询时读取，不缓存图片内容；路径扫描与图片读取不是同一个阶段。
- 配置变更事件向主线程投递重载请求，合并尚未处理的请求。插件 `Update` 只检测重载和导出落盘快捷键，不轮询资源加载、导出缓冲或互操作初始化。

### 显示刷新

UI 资源发布时，若 `LocalizeManager.isSetupCompleted` 已为 true，立即调用 `LocalizeAll(true)`；否则由该属性 setter 的后置回调在初始化完成时触发待处理刷新，不使用逐帧循环。

UI 翻译启用时，`UITranslateManager.Init` 统一安装 I2 翻译和本地化就绪补丁。`Unload` 移除翻译 Hook，但保留就绪回调，确保先关闭 UI 翻译也不会丢失待处理的原生刷新。插件销毁时由 `UITranslateManager.Shutdown` 卸载 UI 模块、清空待刷新状态并移除就绪 Hook。插件入口只调用管理器生命周期方法，不直接管理 UI 补丁。全过程不切换游戏语言。

如果游戏本来就没有某个 term 的原文，I2 返回 null 只是不覆盖当前组件文本，不保证还原旧文本。

通用文本与纹理模块目前只更新后续查询结果；已有显示对象如何刷新，要在接入具体显示入口时实现。

### Harmony 补丁 ID

与 JAT 一样，每个补丁类显式声明稳定、全小写的 `HarmonyId`。同一补丁类的前置、后置和异常清理方法共用所属 ID，不同补丁类使用独立 ID。安装、失败回滚和卸载使用同一个 Harmony 实例，`UnpatchSelf()` 仅移除该 ID 所属的补丁。

| 补丁归属 | Harmony ID |
| --- | --- |
| `UITextTranslatePatch` | `github.meidopromotionassociation.crc3d3.notenoughtranslator.plugin.hooks.ui.uitexttranslatepatch` |
| `LocalizationReadyPatch` | `github.meidopromotionassociation.crc3d3.notenoughtranslator.plugin.hooks.ui.localizationreadypatch` |
| `XUATInterop` | `github.meidopromotionassociation.crc3d3.notenoughtranslator.plugin.utils.xuatinterop` |

这些 ID 用于 Harmony 补丁归属，不是 BepInEx 插件 GUID；插件 GUID 保持不变。后续新增补丁类也应声明独立 ID，不复用模块级简写。

## 6. 接入接口

| 管理器 | 消费接口 | 结果 |
| --- | --- | --- |
| `UITranslateManager` | `TryGetTranslation(term, out translation)` | 按 I2 term 查询文字 |
| `TextTranslateManager` | `TryGetTranslation(sourceText, out translation)` | 精确匹配优先，再尝试正则 |
| `TextureReplaceManager` | `TryGetReplacement(textureName, out data)` | 获取替换图片的编码字节 |

三个管理器都暴露 `IsLoaded`、`IsLoading` 和 `EntryCount`。文本模块另有 `ExactCount` / `RegexCount`，UI 模块另有 `IsHookInstalled`。

### 导出基础设施

`DumpManager` 是共享基础设施，不是另一个翻译模块。插件一次性初始化导出目录，移除各模块 Hook 后关闭导出；通过锁保护本次运行的去重集合与缓冲写入，不使用定时器或逐帧轮询。

| 接口 | 用途 |
| --- | --- |
| `UITranslateManager.DumpTerm(term, original)` | UI 快照发布后导出未翻译词条，包含发布时触发的首次强制刷新 |
| `DumpManager.DumpTerm(term, original)` | 将调用方确认未翻译的词条缓冲为 CSV 模板 |
| `DumpManager.DumpText(original)` | 将调用方确认未翻译的通用文本缓冲为 JSONL 模板 |
| `DumpManager.DumpTexture(textureName, pngData)` | 使用与替换索引相同的文件名规则写入原图 PNG，不覆盖已有文件 |
| `DumpManager.Flush()` | 写入两个文本缓冲并返回是否全部成功 |

I2 查询 Hook 转交未翻译的文本词条，不修改游戏原结果。通用文本正常查询接口仅在加载完成后导出未命中的原文；`IsInTranslationDictionary` 仍只探测词库，不产生导出副作用。首次加载期间不会把尚未就绪的整个词库误当作缺失翻译导出。通用文本显示 Hook、纹理捕获和 PNG 编码仍需游戏接入。

文本写入失败会保留缓冲并尝试恢复原文件长度；PNG 通过临时文件和不覆盖目标的移动操作发布。导出去重记录在资源重载时保留，与 XUAT 的已译文字登记集合彼此独立，不作为翻译查询缓存。开关、阈值与落盘触发条件见[资源指南](翻译指南.md)。

## 7. XUAT 互操作

采用 JAT 的判定拦截方式，反射查找已加载的 `XUnity.AutoTranslator.Plugin.Core`，不需要编译期引用或把 XUAT DLL 放入 `lib`。匹配下列类型中返回 `bool`、第一个参数为 `string` 的 `IsTranslatable` 方法：

- `Utilities.LanguageHelper`
- `TextTranslationCache`
- `CompositeTextTranslationCache`

判定顺序：

1. 输入已登记为 NET 的 UI 或通用文本译文时，返回 `false`，阻止 XUAT 再翻译。
2. 通用文本显示 Hook 已接管，且当前原文能通过精确或正则查询翻译时，也返回 `false`，交给 NET。
3. 其余情况保留 XUAT 原判定；NET 判定发生异常时同样放行，不把全部文本误封。

**第 2 项当前默认不启用。** 通用文本还没有实际显示 Hook，仅加载词库不能保证 NET 会给控件赋值。后续接入代码必须在显示 Hook 成功安装后调用 `TextTranslateManager.SetDisplayHooksInstalled(true)`，移除时传 `false`；模块卸载也会重置该状态。这不是供翻译包开启的设置。

译文登记与查询接口：

- 通用文本 `TryGetTranslation` 在互操作启用时跳过已登记的 NET 译文，并在成功返回后登记结果。
- `IsInTranslationDictionary` 只判断翻译能力，不登记候选结果，避免一次探测就被当作已经输出。
- UI 在参数、RTL 和 `AdvancedFormat` 全部成功后，才通过 `MarkTranslated` 登记最终结果，不登记未展开的模板。
- 两个管理器分别提供 `IsNetTranslatedText` 和 `MarkTranslated`。后续显示 Hook 若还会修改返回值，应登记实际提交的最终文本。
- UI 和通用文本使用独立、线程安全、Ordinal 匹配的译文集合；成功发布新资源或卸载模块时清空各自集合，加载失败仍保留旧状态。
- 集合只用于防重译，不用来返回缓存译文；不包含未命中记录或 LRU，也不做额外规范化、反转义或占位符推测。

插件 `Start` 尝试初始化；晚加载的程序集通过加载事件向 Unity 同步上下文投递回调，在主线程安装补丁，不依赖 `Update` 轮询。互操作卸载后，已排队的回调不再执行安装。未安装 XUAT 时保持普通 NET 行为；签名不兼容或安装失败会记录警告。卸载只移除 NET 自己的 Harmony 补丁，并取消程序集加载事件订阅。

默认启用 `2General` 下的 `EnableXUATInterop/启用 XUAT 互操作`。`XUATInterop.IsInstalled` 和 `PatchedMethodCount` 可用于接入诊断。反射兼容检查不等于真实 XUAT 版本或游戏运行验证。

实现见 [XUATInterop.cs](../../CRC3D3.NotEnoughTranslator.Plugin/CRC3D3.NotEnoughTranslator.Plugin/Utils/XUATInterop.cs) 和 [TranslatedTextRegistry.cs](../../CRC3D3.NotEnoughTranslator.Plugin/CRC3D3.NotEnoughTranslator.Plugin/Translation/TranslatedTextRegistry.cs)。

## 8. 后续接入要求

- 通用文本 Hook 只替换显示值，不修改兼作业务键的名称、CSV 数据或游戏状态。
- 需要处理 I2 调用上下文隔离，避免二次翻译 I2 已处理的显示结果。
- 不能仅凭组件是否挂了 `Localize` 就永久跳过通用翻译；同一个组件仍可能被直接赋值。
- 纹理接入需在 Unity 主线程创建与管理 `Texture` / `Sprite`，明确原资源与替换资源的生命周期。
- 不将当前查询接口或加载计数视为实机覆盖率证明。

## 9. 构建

目标环境：.NET Framework 4.8 / Unity 2022.3 / BepInEx 5。

将 CRC 对应版本的下列程序集放入仓库根目录 `lib`：

- `I2.Localization.dll`
- `Assembly-CSharp.dll`
- `Assembly-CSharp-firstpass.dll`

在仓库根目录执行：

```powershell
dotnet build CRC3D3.NotEnoughTranslator.Plugin/CRC3D3.NotEnoughTranslator.Plugin/CRC3D3.NotEnoughTranslator.Plugin.csproj -c Release
```

异步使用 `Task`，不引入 `System.Threading.Tasks.Extensions` / `ValueTask` 的额外运行时依赖。编译成功不等于完成实机验证。
