# NotEnoughTranslator 翻译与资源指南

[English](../English/TranslationGuide.md) | [返回首页](../../README.md) | [模块架构](模块架构.md)

本文说明 NET 的资源目录、格式、匹配规则与重载方式。模块实现状态及开发接口见[模块架构](模块架构.md)。

**当前是基础骨架：** UI 已有 I2 查询 Hook；通用文本与纹理尚未挂接具体游戏显示入口。资源加载成功不等于已经在游戏中显示译文或替换图片。

## 1. 资源目录

- 配置文件：`BepInEx/config/Github.MeidoPromotionAssociation.CRC3D3.NotEnoughTranslator.Plugin.cfg`
- 翻译根目录：`BepInEx/NotEnoughTranslator`
- UI 文本目录：`BepInEx/NotEnoughTranslator/UI/Text`
- 通用文本目录：`BepInEx/NotEnoughTranslator/Text`
- 纹理目录：`BepInEx/NotEnoughTranslator/Texture`
- 导出根目录：`BepInEx/NotEnoughTranslator/Dump`

这些路径均相对于游戏根目录。

```text
BepInEx/
  NotEnoughTranslator/
    UI/
      Text/
        interface.csv
        ui-pack.zip
    Text/
      common.jsonl
      text-pack.zip
    Texture/
      button.png
    Dump/
      UI/
        Text/
      Text/
      Texture/
```

NET 沿用 JAT 的模块目录结构，但移除目标语言层级。UI 模块只递归读取 `UI/Text` 下的 `.csv`，通用文本模块只递归读取 `Text` 下的 `.jsonl`，纹理只索引 `Texture`。这些是实际的加载边界，不再只是推荐整理方式。直接放在翻译根目录的文件或 ZIP 不会加载，`Dump` 也不会被当作翻译资源扫描。

从旧布局迁移时，将 UI CSV 移入 `UI/Text`，通用文本 JSONL 移入 `Text`，并把 `Textures` 改名为 `Texture`。ZIP 翻译包也要放入对应文本模块的目录，不再兼容扫描旧的公共根目录。

通用文本不读取 `.txt`。没有目标语言子目录或语言选择选项，一份翻译包直接提供要显示的译文。

两个文本模块都可以直接读取各自目录内 ZIP 中对应扩展名的条目，不解压到磁盘，也不递归展开内嵌 ZIP。纹理模块目前只索引 `Texture` 下的散装 PNG / JPG / JPEG 图片，不从 ZIP 读取图片。

## 2. 读取顺序与覆盖关系

1. 各模块先读取自身资源目录的直属文件，按文件名的 Ordinal 顺序排序。
2. 再按目录名的 Ordinal 顺序读取该模块的所有子目录，各目录内的文件也按 Ordinal 顺序排序。
3. ZIP 在其自身的加载位置处理；默认按条目完整名称排序。关闭 `AllowFilesInZipLoadInOrder` 后，改为按归档内原始顺序读取。
4. 相同 UI term 或精确文本原文，后加载的有效条目覆盖前面的条目。
5. 正则按加载顺序逆序尝试，即后加载的规则优先；第一条匹配成功后停止，不串联其他规则。

精确文本匹配始终优先于正则。这里的读取顺序不是游戏显示顺序，也不是翻译命中率统计。

## 3. UI 翻译：CSV

使用 UTF-8 CSV：

```csv
Term,Original,Translation
Example/UI/Confirm,はい,确定
Example/UI/Cancel,いいえ,取消
```

| 列 | 用途 |
| --- | --- |
| `Term` | 游戏的 I2 term，作为精确查询键 |
| `Original` | 原文参考，加载时不参与匹配 |
| `Translation` | 要显示的译文 |

- 必须使用真实游戏 term；示例中的 `Example/...` 只是占位键，未确认存在于游戏中。
- 有表头时，`Term`（或 `Key`）与 `Translation` 按列名定位；支持调整列顺序，表头匹配不区分大小写。
- 也兼容无表头的三列格式：第一列 term、第二列参考原文、第三列译文。
- term 两端空白会被裁剪；空 term 或空白译文忽略。
- 支持双引号字段、字段内逗号、`""` 引号转义和引号内的实际换行。可使用 `#` 或 `//` 开头的注释行。
- CSV 中的反斜杠不做自定义转义。需要换行时，使用引号包围的实际多行字段。
- UI Hook 不将已知的字体、精灵等非文本 term 当作文字翻译。

### 参数与花括号

当 term 实际使用 `AdvancedFormat` 格式化时，译文须保留需要的 `{0}` 等占位符，字面花括号遵守 `string.Format` 的 `{{` / `}}` 规则。

I2 处理异常时保留游戏原结果，同一 term 每轮资源加载只警告一次。不要通过改变游戏语言或开启全局多语言来处理缺译问题。

## 4. 通用文本：JSONL

每行一个 UTF-8 JSON 对象：

```jsonl
{"original":"はい","text":"是"}
{"original":"アリス","text":"爱丽丝"}
{"original":"^(?<name>.+)の所持金：(?<amount>\\d+)円$","text":"${name} 的持有金：${amount} 日元","regex":true}
{"original":"^残り (\\d+) 秒$","text":"剩余 $1 秒","regex":true}
```

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `original` | 字符串，必需且非空 | 精确原文，或正则模式 |
| `text` | 字符串，必需 | 译文，或正则替换字符串 |
| `regex` | 布尔值，可省略 | `true` 为正则；省略或 `false` 为精确匹配 |

通用文本 JSONL 只接受 `original`，不把 `term` 当作别名；UI CSV 的 `Term` 列不受影响。

不使用 JAT 的 TXT 文件、行首 `$` 正则标记或自定义多语言字符串语法。

### 4.1 精确匹配

按原文做 Ordinal 精确匹配，区分大小写，不裁剪原文或做隐式规范化。空白译文会被忽略。

### 4.2 正则替换

一条正则规则由两种不同的语法组成：

| 字段 | 使用的语法 | 例子 |
| --- | --- | --- |
| `original` | .NET 正则**模式**，决定匹配什么 | `^残り (\d+) 秒$` |
| `text` | .NET 正则**替换字符串**，决定如何组织译文 | `剩余 $1 秒` |

表中是 JSON 解析后的内容；实际 JSONL 中的反斜杠必须写成 `\\`。完整条目如下：

```jsonl
{"original":"^残り (\\d+) 秒$","text":"剩余 $1 秒","regex":true}
```

输入 `残り 30 秒`，输出 `剩余 30 秒`：

1. `^` 从字符串开头匹配，`残り ` 和 ` 秒` 按字面匹配，包括空格。
2. `(\d+)` 捕获连续数字 `30`，作为第 1 个捕获组。
3. `$` 匹配结尾；`text` 中的 `$1` 引用第 1 组，代入译文。

`残り30秒` 不匹配这条规则，因为少了模式中要求的空格。

查询时的执行顺序：

XUAT 互操作启用时，通用文本查询会先跳过已登记的 NET 译文，防止再次翻译。其余输入按以下顺序处理，详见第 8 节。

1. 先查**整段原文的精确字典**；命中就返回，不尝试正则。
2. 未命中时，按[读取顺序](#2-读取顺序与覆盖关系)逆序尝试正则；后加载的规则先尝试。
3. 第一条匹配成功的规则通过 `Regex.Replace` 替换**全部匹配**，未匹配的部分原样保留。
4. 返回该规则的结果，不再串联下一条规则，也不重新翻译生成的文本。即使结果与原文相同或变为空字符串，这条规则也算命中。

必须设置 `"regex":true`；省略时，即使 `original` 看起来像正则，也只是精确原文。不要套用 JavaScript 的 `/模式/g` 写法，也不要添加 JAT 的行首 `$` 标记。不做 LRU、命中缓存或未命中缓存；正则在加载时编译。

### 4.3 常用模式语法

以下写法都是**JSON 解析后的正则模式**，复制到 JSONL 时还需要按 4.6 节处理反斜杠：

| 写法 | 含义与注意事项 |
| --- | --- |
| `^`、`$` | 默认匹配字符串开头、结尾；`$` 也可匹配末尾换行符之前。开启 `(?m)` 后还会匹配每行边界 |
| `\A`、`\z` | 严格匹配整个字符串的开头、结尾，不受 `(?m)` 影响；需要整段精确覆盖时推荐使用 |
| `(表达式)`、`$1` | 模式中的括号建立编号捕获组；替换字符串用 `$1` 引用 |
| `(?<name>表达式)`、`${name}` | 建立并引用命名捕获组；规则复杂时推荐命名，避免调整括号后引用错位 |
| `(?:表达式)` | 只分组，不建立捕获组 |
| `[0-9]+` | 一个或多个 ASCII 数字；`\d+` 的范围更广，也能匹配全角数字等 Unicode 十进制数字 |
| `.`、`.+`、`.*` | 任意一个、一个或多个、零个或多个字符；默认的 `.` 不匹配换行符 `\n` |
| `.*?`、`.+?` | 非贪婪匹配，优先匹配较短内容；不代表自动更快或更安全 |
| `[^：\r\n]+` | 一个或多个非全角冒号、非换行字符，适合限制名称等字段的边界 |
| `\s*`、`\s+` | 零个或多个、一个或多个空白字符，**包括换行**；只允许普通空格和制表符时使用 `[ \t]*` / `[ \t]+` |
| `\r?\n` | 匹配常见的 LF 或 CRLF 换行 |
| `?`、`{2,4}` | 前一个元素出现零次或一次、出现 2 至 4 次 |
| `\.`、`\[`、`\(` | 匹配字面上的点、左方括号、左圆括号，而不是把它们解释为正则语法 |
| `(?i)` | 后续模式忽略大小写；默认区分大小写 |
| `(?m)` | 多行模式，改变 `^` / `$` 的含义，**不会**让 `.` 跨行 |
| `(?s)` | 单行模式，让 `.` 也匹配换行；名称虽叫“单行”，通常用于捕获跨行内容 |

`A|B` 表示二选一；整句匹配时应写成 `^(?:A|B)$`，不要误写成 `^A|B$`。可组合内联选项，例如 `(?is)` 同时忽略大小写并允许点号跨行。

### 4.4 捕获内容二次翻译

引用捕获组时，NET 会把**该捕获组的完整值**查一次通用文本的精确翻译字典，再代入替换字符串。这是保留的翻译功能，不是额外的转义语法。

```jsonl
{"original":"アリス","text":"爱丽丝"}
{"original":"^(?<name>.+)の所持金：(?<amount>[0-9]+)円$","text":"${name}的持有金：${amount}日元","regex":true}
```

| 输入 | 输出 |
| --- | --- |
| `アリスの所持金：100円` | `爱丽丝的持有金：100日元` |
| `ボブの所持金：50円` | `ボブ的持有金：50日元` |

第一行输入的处理过程是：

1. `name` 捕获 `アリス`，精确字典命中，替换为 `爱丽丝`。
2. `amount` 捕获 `100`，精确字典未命中，保留 `100`。
3. 用这两个值组成最终译文。

注意边界：

- 二次翻译使用本次已加载的**通用文本精确字典**，不是 UI CSV / I2 词条。
- 名称、数字等捕获组都按相同方式查询，不只翻译某个特定组名。捕获值包含的空格也参与精确匹配。
- 不拆分捕获内容逐词翻译，不对捕获内容再次应用正则，也不递归翻译字典返回的译文。
- 如果只有 `アリス → 爱丽丝`，捕获值却是 `アリスさん`，不会自动变成 `爱丽丝さん`。需要把后缀放在组外，或增加完整精确词条。
- 捕获值或其译文包含 `$1`、`${name}` 等字符时，会原样插入，不会被当作新的一轮替换引用。

### 4.5 替换引用速查

以下语法只适用于正则规则的 `text`，由 .NET 的 `Match.Result` 解释：

| 写法 | 含义 | 二次精确翻译 |
| --- | --- | --- |
| `$1`、`${1}` | 第 1 个捕获组 | 是，捕获成功时 |
| `${name}` | 名为 `name` 的捕获组 | 是，捕获成功时 |
| `$0`、`${0}`、`$&` | 当前这一次的完整匹配，不一定是整段输入 | 是 |
| `$+` | .NET 的最后捕获组引用 | 是 |
| `$$` | 一个字面上的美元符号 `$` | 否 |
| `` $` `` | 原输入中位于当前匹配之前的内容 | 否 |
| `$'` | 原输入中位于当前匹配之后的内容 | 否 |
| `$_` | 整段原始输入 | 否 |

- 使用 `${1}0` 表示“第 1 组后面接字符 `0`”；`$10` 是第 10 组引用，不是 `$1` 加 `0`。
- `\1` 不是替换字符串的捕获引用；也不要使用 I2 / `string.Format` 风格的 `{0}`。NET 的通用文本模块不会额外解释它们。
- 可选捕获组未参与本次匹配时，标准组引用展开为空；拼错或不存在的组引用可能按 .NET 规则原样保留，不应依赖它报错。
- 重复捕获的同一组被引用时取最终的 `Group.Value`，不会自动把所有历史捕获逐个拼接。
- `Regex.Replace` 本来就会保留未匹配的前后文，再用前文、后文或整段输入引用，可能重复这些内容。普通翻译优先使用命名捕获组。

例如，要在数字前输出一个字面上的 `$`：

```jsonl
{"original":"^価格：([0-9]+)$","text":"价格：$$$1","regex":true}
```

输入 `価格：100`，输出 `价格：$100`。`$$` 输出美元符号，随后 `$1` 输出数字。精确翻译条目的 `text` 不解释这些引用，直接写 `$` 即可。

### 4.6 JSON 转义与正则语法的区别

**没有自定义转义，不等于 JSON 中可以随便写反斜杠。** 数据依次经过两个标准解释步骤：

```text
JSONL 文件 -> JSON 字符串解析 -> original 作为正则模式 / text 作为替换字符串
```

| 目的 | JSON 文件中的字符串 | JSON 解析后的内容或效果 |
| --- | --- | --- |
| `original` 匹配数字 | `"\\d+"` | 正则 `\d+` |
| `original` 匹配字面上的点 | `"\\."` | 正则 `\.` |
| `original` 匹配一个反斜杠 | `"\\\\"` | 正则 `\\` |
| `text` 输出实际换行 | `"第一行\n第二行"` | 输出两行文字 |
| `text` 输出字面上的 `\n` | `"第一行\\n第二行"` | 输出 `第一行\n第二行`，不产生换行 |
| `text` 输出双引号 | `"她说：\"你好\""` | 输出 `她说："你好"` |
| `text` 输出路径 | `"C:\\Mods"` | 输出 `C:\Mods` |
| 正则 `text` 输出 `$` | `"$$"` | 输出 `$`，这是替换语法，不是 JSON 转义 |

JSON 中直接写 `"\d+"` 是非法转义；必须写 `"\\d+"`。正则模板中的 `$1` / `${name}` 不需要额外的 JSON 转义。

`"\\n"` 解析后虽然都是反斜杠加 `n`，但在 `original` 中会被正则引擎解释为匹配换行，在 `text` 中则保持这两个字符。要让译文换行，写 JSON 的 `"\n"`。

JSONL 的每个对象仍须占一个物理行；需要换行内容时使用 JSON 转义，不要把一个对象手工拆成多行。不要加入注释或尾随逗号。

NET 不再额外调用自定义 `Unescape` 或 `Regex.Unescape` 来转换翻译内容。

### 4.7 更多完整示例

以下各组示例相互独立，可以单独保存为 JSONL。输入、输出展示的是翻译查询的行为，不代表尚未挂接的游戏显示入口已经生效。

#### 调整语序与容忍空格

```jsonl
{"original":"\\A所持数：[ \\t]*(?<current>[0-9]+)[ \\t]*/[ \\t]*(?<limit>[0-9]+)\\z","text":"上限 ${limit}，当前 ${current}","regex":true}
```

输入 `所持数： 3 / 10`，输出 `上限 10，当前 3`。命名引用可以改变原文中的参数顺序；`[ \t]*` 容忍空格和制表符，但不会吞掉换行。

#### 局部替换与一条规则的多次匹配

```jsonl
{"original":"HP","text":"体力"}
{"original":"MP","text":"魔力"}
{"original":"(?<stat>HP|MP):[ \\t]*(?<value>[0-9]+)","text":"${stat}：${value}","regex":true}
```

输入 `HP: 10 / MP: 5`，输出 `体力：10 / 魔力：5`。模式没有整句锚点，同一条规则匹配并替换两处，斜杠和周围空格原样保留；`HP` / `MP` 分别通过捕获内容二次翻译得到中文。

#### 匹配字面上的方括号

```jsonl
{"original":"設定","text":"设置"}
{"original":"\\A\\[体験版\\] (?<title>.+)\\z","text":"[体验版] ${title}","regex":true}
```

输入 `[体験版] 設定`，输出 `[体验版] 设置`。`original` 中的方括号必须按正则语法转义，`text` 中的方括号只是普通文字，不需要转义。

#### 跨行捕获与输出换行

```jsonl
{"original":"1行目\n2行目","text":"第一行\n第二行"}
{"original":"(?s)\\A説明：(?<body>.+)\\z","text":"说明：\n${body}","regex":true}
```

输入为两行：

```text
説明：1行目
2行目
```

输出为三行：

```text
说明：
第一行
第二行
```

`(?s)` 让 `body` 捕获跨行内容，整个 `1行目\n2行目` 再命中精确词条。只分别提供 `1行目` 和 `2行目` 的词条不会产生同样的二次翻译，因为捕获值不会自动逐行拆分。

#### 用空替换删除前缀

```jsonl
{"original":"^\\[仮\\][ \\t]*","text":"","regex":true}
```

输入 `[仮] 設定`，输出 `設定`。这只是删除前缀；即使另有精确词条 `設定 → 设置`，本次结果也不会再次送回字典翻译。

### 4.8 精确词条与正则规则的优先级

同一个文件按以下顺序写入：

```jsonl
{"original":"^残り (?<seconds>[0-9]+) 秒$","text":"剩余 ${seconds} 秒","regex":true}
{"original":"^残り 0 秒$","text":"时间到","regex":true}
{"original":"残り 5 秒","text":"最后五秒"}
```

| 输入 | 输出 | 原因 |
| --- | --- | --- |
| `残り 0 秒` | `时间到` | 后加载的特殊正则先尝试 |
| `残り 5 秒` | `最后五秒` | 整段精确词条始终优先于正则 |
| `残り 10 秒` | `剩余 10 秒` | 特殊正则不匹配，再尝试通用正则 |

将过于宽泛的规则放在更后面，会遮住前面的特殊规则。`.*` 甚至能匹配空串并多次插入内容，不适合作为通用的“缺失翻译兜底”。优先写有明确前缀、分隔符和字段边界的模式。

### 4.9 错误、超时与排查

语法错误的 JSONL 条目或正则会记录文件/行号并跳过，不中止其他条目。正则执行超时则停用该规则至下次重载，避免每帧重复阻塞；默认超时为 100ms，通过 `RegexTimeoutMilliseconds` 配置。

遇到不生效或结果异常时，依次检查：

1. 是否设置了 `"regex":true`，JSON 反斜杠是否正确，日志是否提示该行被跳过。
2. 是否已有整段精确译文，或另一条后加载的正则提前命中。
3. 输入中的半角 / 全角标点、空格、大小写、换行和富文本标签是否与模式一致。引擎不会先替你去掉标签或整理空白。
4. 捕获组名与引用是否一致，二次翻译词条是否与捕获值完全一致。
5. 规则是否已超时停用；修正后需要重载。避免 `(.+)+` 等容易产生大量回溯的嵌套重复，不要只靠调大超时掩盖问题。

使用外部正则工具时选择 **.NET** 引擎；先验证 JSON 解码后的模式，再核对实际 JSONL。其他引擎的语法、替换引用和选项不一定兼容。

## 5. 纹理替换资源

将 PNG / JPG / JPEG 文件放入 `Texture` 目录及其子目录。

- 按不区分大小写的文件名匹配，忽略目录，以及 `.tex` / `.png` / `.jpg` / `.jpeg` 扩展名。
- 例如 `button`、`button.tex`、`button.png` 可以查询名为 `button.png` 的替换资源。
- 重名时后加载的文件覆盖并告警；子目录不会形成独立的纹理名称空间。
- 目前只保存路径索引，查询时读取文件，不缓存图片内容，不修改或销毁游戏纹理。

`TextureReplaceManager.TryGetReplacement(textureName, out byte[] data)` 返回图片编码数据，未命中返回 `false`。此接口不等于已经接入游戏替换；实际资源 Hook 与 Unity 对象管理仍待实现，见[模块架构](模块架构.md)。

## 6. 开关与热重载

- 三模块分别使用 `3UI`、`4Text`、`5Textures` 配置节中的 `Enabled/启用` 开关。
- 开关、正则超时或 ZIP 读取顺序变化，会在主线程触发资源重载。
- 可配置 `ReloadTranslateResource` 快捷键；默认未绑定，按下时只触发一次。
- 不自动监视文件变化；修改翻译文件后，需要主动触发重载。
- 重载过程中保留上次资源快照。文件读取失败时保留旧快照，成功读取空目录时清空旧资源。
- JSONL 的单条格式错误按前述规则跳过，不属于整批文件读取失败。

UI 重载会强制刷新 I2；通用文本与纹理目前仅改变后续查询结果。若游戏没有某个 term 的原文，I2 的 null 结果不能保证还原控件旧文本。

### 未翻译资源导出

插件启动时创建 `Dump/UI/Text`、`Dump/Text` 和 `Dump/Texture`。通过 `6Dump` 配置节按需启用导出，三个导出开关默认均关闭。

- `EnableTermDump`：首份 UI 快照发布后，将未翻译的文本词条查询导出为 `Term,Original,Translation` CSV。`Original` 是游戏返回的显示文字，`Translation` 初始为空；跳过非文本词条和显式指定语言的查询。需要保持 UI 模块启用；可触发资源重载，让当前已显示 UI 再执行一次本地化以采集词条。
- `EnableTextDump`：已加载的通用文本查询接口未命中时，导出 `{"original":"原文","text":""}` 形式的 JSONL。只探测词库的接口不导出；实际游戏文本采集仍依赖待接入的显示 Hook。
- `EnableTexturesDump`：允许 `DumpManager.DumpTexture(textureName, pngData)` 写入已捕获的原图 PNG。该接口不会枚举游戏纹理、读取 GPU 数据或实现捕获 Hook；不覆盖已有文件，也不会把未完整写入的临时文件发布为 PNG。
- UI 词条和通用文本分别按 Ordinal 规则在本次插件运行期间去重，热重载不清空去重记录。CSV 引号规则和 JSON 转义会保留逗号、引号、反斜杠与换行，不另存归一化 TXT 副本。
- `TermDumpThreshold` 与 `TextDumpThreshold` 默认均为 `100`。达到阈值、按下可选的 `FlushDump` 快捷键、修改导出配置、重载资源或退出插件时写入缓冲；不定时或逐帧写盘。失败时保留缓冲供后续显式重试，但进程崩溃仍可能丢失尚未写入的记录。

CSV 和 JSONL 分别写入带时间戳的独立会话文件。补全空的译文列后，把文件放入 `UI/Text` 或 `Text` 并重载；PNG 编辑完成后放入 `Texture`。文件留在 `Dump` 下不会自动作为翻译资源生效。

## 7. 示例与限制

第 3、4 节示例用于说明格式，不是实际游戏翻译包。加载条目数不等于游戏覆盖率。制作翻译时不要改写兼作业务键的原始数据；具体显示接入、I2 隔离与纹理生命周期要求见[模块架构](模块架构.md)。

## 8. XUAT 互操作

NET 可与 XUnity.AutoTranslator 共存，采用 JAT 式的 `IsTranslatable` 判定拦截，而不是向文字中添加或检测特殊标记。翻译包仍使用原来的 CSV / JSONL，不需要写入不可见字符或额外转义。

- `2General` 的 `EnableXUATInterop/启用 XUAT 互操作` 默认开启；未安装 XUAT 时自动跳过，不是强制依赖。
- 实际被 NET 返回并登记的 UI / 通用文本译文，会被拦在 XUAT 的翻译判定之外；正则动态结果也可登记，不只识别静态字典中的译文。
- 原文是否属于 NET 词库，由精确与正则查询判断；但只有通用文本显示 Hook 确实接管后才阻止 XUAT 抢译。
- **当前通用文本仍是查询骨架，没有实际显示 Hook，因此原文默认放行 XUAT。** 互操作不会凭空让 JSONL 译文显示出来，也不影响 XUAT 对未接管文本的正常处理。
- 不调用 XUAT 翻译回调来替代显示 Hook，不修改 XUAT 语言、翻译文件或特殊标记设置。
- 成功重载或卸载某模块会清空该模块的已译文登记；已有控件是否重新赋值仍遵循前面的刷新边界，登记本身不会刷新画面。

已译文登记只是去重用的文本集合，不保存“原文 → 译文”缓存，也不引入 LRU。发生判定异常时交还 XUAT，而不是阻止其翻译全部文本。开发接口、接管状态和生命周期见[模块架构](模块架构.md#7-xuat-互操作)。
